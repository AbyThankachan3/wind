# Wind Exposure Pipeline

Turns NASA NEX-GDDP-CMIP6 climate projections into per-country, web-servable
wind-exposure raster layers (Cloud-Optimized GeoTIFFs), for the years 2030–2100
under two emissions scenarios.

Pipeline stages (all orchestrated by `run_all.py`):

| Step | Script | Does |
|---|---|---|
| 00 | `download_shapefile.py` | Fetch the country boundary shapefile (official source) |
| 01 | `01-download-wind-data.py` | Download raw global `sfcWind` NetCDF from NASA |
| 02 | `02-derived.py` | Clip to country + per-model yearly stats |
| 03 | `03-ensemble-derived.py` | Combine across ~35 models |
| 04 | `04-multiband-tiff-creation.py` | Stack the 5 layers per scenario |
| 05 | `05-cog.py` | Convert to Cloud-Optimized GeoTIFFs (final output) |
| 06 | `06-cleanup.py` | Delete regenerable intermediates (keeps raw `.nc` + COGs) |

Output layers per year/scenario: `baseline_wind_exposure`, `severe_wind_exposure`,
`peak_wind_exposure`, `strong_wind_frequency`, `confidence`. See
[docs/frontend-layer-info.md](docs/frontend-layer-info.md) for the meaning of each.

## Configuration

All settings live in `config.py` and can be overridden by environment variables
(handy for Docker/CI):

| Env var | Default | Meaning |
|---|---|---|
| `WIND_COUNTRY` | `Canada` | single country to process |
| `WIND_COUNTRIES` | *(unset)* | process several at once: a list (`Canada,UK`) or `all`. Takes precedence over `WIND_COUNTRY` |
| `WIND_DATA_ROOT` | next to `config.py` | base folder for all data (Docker: `/data`) |
| `WIND_GIS_DIR` | `../GIS Files` | base folder the boundary shapefiles land in |
| `WIND_YEARS` | `2030…2100` | comma-separated years |
| `WIND_SSPS` | `ssp245,ssp585` | comma-separated scenarios |
| `WIND_THRESHOLD_MS` | `12` | strong-wind threshold (m/s) |
| `WIND_PROCESS_WORKERS` | `2` | step-02 CPU workers → RAM: 16GB=1, 32GB=4, 64GB=6 |
| `WIND_KEEP_INTERMEDIATE` | *(unset)* | `1` keeps derived/`_multimodel` instead of deleting |
| `WIND_RAW_DIR` / `WIND_OUTPUT_ROOT` / `WIND_SHAPEFILE` | *derived* | advanced path overrides |

You do **not** type a shapefile path: step 00 downloads it and its location is
derived from the country name. Adding a new country = register its download in
`download_shapefile.py` and its resulting filename in `config.py`
(`SHAPEFILE_BY_COUNTRY`).

### Multiple countries in one run

The raw NASA data is **global**, so it's downloaded **once** into a shared
`raw_nc/` folder and clipped to each country — processing many countries does
**not** re-download it.

```bash
WIND_COUNTRIES=all docker compose run --rm wind python run_all.py --yes
```

`run_all.py` then downloads once, then loops the countries doing only
clip→stats→COG for each. Preview the plan without downloading anything:

```bash
python run_all.py --dry-run
```

## Run it — Docker (recommended)

Reproducible; no local Python or GDAL needed.

```bash
# 1. Point the data volume at a disk with 100+ GB free (edit docker-compose.yml).
# 2. Build and run:
docker compose up --build
```

All output — including the downloaded shapefile and the multi-GB NASA data —
lands on the mounted host folder (`./data` by default, change it in
`docker-compose.yml`). Re-running skips files already downloaded.

To run a different **registered** country, change only the country — the
shapefile path is derived from it:

```bash
WIND_COUNTRY=UK docker compose run --rm wind python run_all.py --yes
```

## Run it — native (no Docker)

Needs Python 3.10+ (installed with "Add to PATH").

- **Windows:** double-click `run.bat`
- **macOS / Linux / Git Bash:** `./run.sh` (if "permission denied", `chmod +x run.sh` once)

Either one creates a local `.venv`, installs `requirements.txt`, and runs the
same steps 00–05 — just without a container. On the first run it also prints a
summary and waits for you to press Enter before the large download.

> Docker is recommended over this: it packages the GDAL/geospatial libraries so
> a dependency can't fail to install on your machine (which it can, natively).

## Heads-up before the first run

- **Large download.** Step 01 pulls *global* NASA files (~35 models × 2 scenarios
  × 8 years); clipping to the country happens afterwards. Expect **tens of GB**
  and a multi-hour run. Make sure the data volume/disk has room.
- **Resumable.** Completed `.nc` files are skipped on re-run; a partially
  downloaded file (`.part`) is restarted cleanly.
- **Data is git-ignored.** The repo is code only. `WindData/`, `data/`, and
  `GIS Files/` are excluded — they are regenerated by running the pipeline.
- **Auto-cleanup (step 06).** After a successful run, the regenerable
  intermediates (`derived/`, `_multimodel/`, pre-COG `results/*.tif`) are
  deleted, keeping the raw `.nc`, the shapefile, and the final COGs. Set
  `WIND_KEEP_INTERMEDIATE=1` to keep everything. Note this keeps the large raw
  downloads — re-run steps 02–05 anytime to rebuild layers without
  re-downloading.

## Output

Final deliverables:

```
<data>/WindData/<Country>/results/cog/<year>_<scenario>.tif
```

Each is a 5-band Cloud-Optimized GeoTIFF (e.g. `2030_ssp245.tif`):

| Band | Layer | Units |
|---|---|---|
| 1 | baseline_wind_exposure | m/s |
| 2 | severe_wind_exposure | m/s |
| 3 | peak_wind_exposure | m/s |
| 4 | strong_wind_frequency | days/year |
| 5 | confidence | ratio |

A download log is written to `<data>/WindData/<Country>/manifests/download_manifest.csv`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Step 02 killed / "OpenBLAS memory" / OOM | Lower `WIND_PROCESS_WORKERS` (16 GB RAM → 1) |
| "No space left on device" (Docker or pip) | The data drive or C: is full — free space or move the data volume to a bigger drive |
| A step stopped | The message names it. Re-running is safe and resumes downloads; send the last ~30 lines to the team |
| "Could not determine the shapefile path for '\<country\>'" | That country isn't registered yet — see *Adding a country* |
| Docker won't start / daemon error | Ensure Docker Desktop is running and its data disk (usually on C:) has space |

## Adding a country

1. Register its **download** in `download_shapefile.py` (`SOURCES`) and its
   **resulting filename** in `config.py` (`SHAPEFILE_BY_COUNTRY`)
   — see [docs/boundary-data-sources.md](docs/boundary-data-sources.md) for verified sources.
2. Set `WIND_COUNTRY` to that country.
3. Run. Registration-gated sources (some Gulf states) print manual instructions.
